# Создание сети и подключение нод

Статус: план, документ не наполнен.  
Назначение: описать пользовательские сценарии первого запуска: создание новой сети,
подключение ноды с UI и подключение headless-ноды.

Связанные документы: [identity и доверие](../06-network/02-identity-and-trust.md),
[control log](../06-network/03-control-log.md),
[NAT и достижимость](./02-nat-and-reachability.md),
[системная оболочка](../10-clients/04-system-shell.md).

Механизм enrollment и работы с ключами описан в документе об identity; здесь описываются
сценарии и то, что видит пользователь.

## Что войдёт в документ

### Создание сети

- первый запуск настольного или мобильного приложения: выбор между созданием новой сети и
  присоединением к существующей;
- при создании новой сети приложение становится единственной нодой сети;
- создание profile root key и предъявление recovery phrase пользователю;
- что происходит, если пользователь пропустил сохранение recovery phrase.

### Подключение новой ноды с UI

- код подключения генерирует нода, которая ещё не в сети; сканирует его любая нода,
  уже входящая в сеть, кроме headless;
- способы передачи кода: QR-код и ручной ввод;
- состав кода: как подключиться к ноде и её идентификатор;
- взаимная проверка короткой строки аутентификации перед выдачей ключей;
- роль, назначаемая новой ноде, и подтверждение пользователем.

### Подключение headless-ноды

- headless-нода может только присоединяться и не может создать сеть;
- при первом запуске она печатает свой код, который пользователь вставляет в UI любой
  ноды сети;
- сценарий облачной ноды с постоянным адресом;
- сценарий ноды без экрана в локальной сети, например контроллера умного дома;
- что делать, если такая нода ещё не подключена к локальной сети.

### Дальнейшие операции

- отзыв ноды и последствия для данных на ней;
- переустановка ноды и восстановление профиля;
- восстановление сети при утрате всех устройств с правами администратора.

## Исходные требования

- настольные и мобильные приложения при первом запуске могут либо создать новую сеть,
  либо подключиться к существующей;
- при создании новой сети приложение становится единственной нодой сети;
- для подключения новой ноды нужно сосканировать QR-код или ввести код вручную;
- код генерирует нода, не входящая в сеть, а сканирует любая нода в сети, кроме headless;
- headless-нода может только подключаться, создавать сеть не может: при первом запуске она
  печатает свой код, который нужно вставить в UI любой ноды сети;
- код должен содержать информацию о том, как подключиться к ноде, и её идентификатор.

## Открытые вопросы

- почему код генерирует подключаемая нода, а не сеть: это решение продиктовано проблемой
  достижимости и должно быть согласовано с [документом о NAT](./02-nat-and-reachability.md);
- срок жизни кода подключения и поведение при его утечке;
- допустимо ли подключение по коду, введённому вручную, без визуального подтверждения на
  обеих сторонах;
- как подключается headless-нода, ещё не имеющая сетевой конфигурации.
