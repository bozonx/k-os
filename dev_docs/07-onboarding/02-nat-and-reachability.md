# NAT и достижимость нод

Статус: план, документ не наполнен.  
Назначение: зафиксировать проблему достижимости нод за NAT и выбрать способы её решения
для каждого сценария подключения и повседневной работы.

Связанные документы: [каналы и транспорт](../06-network/04-transport-and-discovery.md),
[создание сети и подключение нод](./01-network-lifecycle.md),
[облачная нода](../10-clients/03-cloud-node.md).

## Проблема

Нода, находящаяся за NAT, недостижима извне без дополнительных механизмов. Это влияет и на
первое подключение, и на повседневную синхронизацию, и на связь между сетями разных
пользователей.

Сценарии различаются по сложности:

| Сценарий | Сложность |
|---|---|
| Обе ноды в одной локальной сети | проблемы нет |
| Облачная нода с постоянным адресом | проблемы нет |
| Headless-нода без экрана в чужой или новой локальной сети | требуется решение |
| Две сети разных пользователей, обе за NAT | требуется решение |
| Мобильное устройство в сотовой сети | требуется решение |

## Что войдёт в документ

- разбор каждого сценария и применимого к нему механизма;
- проброс порта через маршрутизатор автоматическими средствами и его ненадёжность;
- инициирование соединения со стороны подключаемого устройства вместо приёма входящего;
- использование постоянно доступной ноды как точки встречи;
- прямое соединение через посредника и условия, при которых оно возможно;
- ретрансляция через узел без доступа к данным как гарантированный путь;
- обнаружение в локальной сети без раскрытия постоянных идентификаторов;
- альтернативные каналы, не требующие маршрутизации: Bluetooth, mesh, проводные соединения;
- деградация: что перестаёт работать, если ни один механизм не сработал, и как это
  показывается пользователю;
- влияние выбранного механизма на приватность: какие метаданные видит посредник.

## Исходные требования

- проблема NAT существует и должна быть решена явно;
- варианты: проброс порта через маршрутизатор либо инициирование соединения со стороны
  подключающегося устройства;
- при подключении устройств с UI проблема обычно отсутствует, поскольку они находятся в
  одной локальной сети;
- основная сложность — подключение headless-устройств;
- облачная нода имеет постоянный адрес, поэтому для неё проблемы нет;
- нода без экрана в локальной сети требует, чтобы пользователь сначала подключил её к сети
  и затем ввёл код.

## Открытые вопросы

- какой механизм обхода NAT входит в базовую поставку, а какой устанавливается отдельно;
- обязателен ли посредник для связи между сетями двух пользователей, если у обоих нет
  постоянно доступной ноды;
- нужен ли собственный протокол установления прямого соединения или используется готовый;
- как система сообщает пользователю, что его сеть работает ненадёжно из-за отсутствия
  постоянно доступной ноды.
