# Модель угроз

Статус: готов  
Назначение: перечислить защищаемые активы, противников и применяемые к ним меры, зафиксировать
допущения и то, от чего система намеренно не защищает.

## Активы

| Актив | Почему ценен | Где находится |
|---|---|---|
| данные профиля: файлы, состояние приложений | основное содержимое среды | на всех нодах профиля |
| секреты приложений и профиля | дают доступ к внешним сервисам | отдельный класс хранения |
| profile root key | восстановление профиля, высшие полномочия | recovery phrase, офлайн |
| ключи нод | членство в профиле | платформенное хранилище, не покидают устройство |
| эпохи ключей данных | расшифровка записей и содержимого | все ноды с ключами профиля |
| control log | состав профиля и права | реплицируется |
| доступ к оборудованию и подключённым устройствам | физические последствия | ноды с оборудованием |
| метаданные: состав сети, активность, объёмы | профилирование пользователя | видны транзитным узлам |

## Доверенная вычислительная база

```text
Доверено                                  Не доверено
├── ядро K-OS: control plane,             ├── Web UI приложений
│   services, drivers, host adapters      ├── WebAssembly-воркеры приложений
├── платформенные расширения              ├── содержимое пакетов до проверки подписи
│   (устанавливаются явно)                ├── связанные пользователи
├── платформенное хранилище ключей        ├── узлы ретрансляции
├── ОС и оборудование ноды                └── любой сетевой участник до аутентификации
└── ноды профиля с ключами данных
```

Существенно, что **облачная нода и нода умного дома входят в доверенную базу**: они владеют
ключами данных. Для сценария «не доверяю хостингу» существует роль `relay`, не имеющая
ключей.

## Границы безопасности

Граница безопасности — место, где недоверенная сторона останавливается. Ниже перечислены все
границы системы и документ, который каждую из них определяет; формулировка самой границы
живёт там, а не здесь.

| Граница | Определена в |
|---|---|
| данные пакета отделены от данных других пакетов | [модель состояния](../05-storage/01-state-model.md) |
| Web UI работает через ограниченный bridge, воркер — в WebAssembly sandbox | [изоляция](./01-isolation.md) |
| системные capabilities запрещены по умолчанию, права выдаются явно | [модель capabilities](../04-capabilities/01-model.md) |
| доступ к пользовательским файлам — через picker, scope или permission | [VFS](../05-storage/03-vfs.md) |
| credentials хранятся в secrets service, а не в манифесте | [каталог: хранилище](../04-capabilities/02-catalog/03-data.md) |
| сетевые права ограничены хостом и протоколом | [базовый стек](../02-architecture/06-base-stack.md) |
| фоновые права и права администрирования выдаются отдельно | [каталог: система](../04-capabilities/02-catalog/06-system.md) |
| межпакетный вызов разрешают обе стороны и система | [каталог: события и команды](../04-capabilities/02-catalog/02-events-and-commands.md) |
| запуск программ хоста и выход за пределы VFS — отдельный класс прав | [каталог: инструменты](../04-capabilities/02-catalog/05-tools.md) |
| обновление пакета не расширяет права молча | [распространение](../03-apps/07-distribution.md) |
| нода имеет отдельную identity, добавление требует подтверждения человеком | [identity и доверие](../06-network/02-identity-and-trust.md) |
| транспорт взаимно аутентифицирован и зашифрован независимо от канала | [каналы и транспорт](../06-network/04-transport-and-discovery.md) |
| данные шифруются на уровне записей и blobs, а не только в канале | [репликация](../06-network/07-replication.md) |
| удалённое исполнение требует delegation и согласия целевой ноды | [удалённые вызовы](../06-network/06-rpc-and-delegation.md) |
| отзыв ноды влечёт новую эпоху ключей | [identity и доверие](../06-network/02-identity-and-trust.md) |
| relay не получает ключей и проверяет авторизацию по control log | [control log](../06-network/03-control-log.md) |
| discovery не раскрывает стабильные идентификаторы до аутентификации | [каналы и транспорт](../06-network/04-transport-and-discovery.md) |

Основная граница — capability gateway в Rust. Все остальные усиливают её, но ни одна не
заменяет: при компрометации любой из них приложение по-прежнему ограничено выданными
capabilities.

## Противники и меры

### Недоверенное приложение

Установленный пользователем пакет, который ведёт себя злонамеренно.

| Что пытается | Что мешает |
|---|---|
| обратиться к ОС и файлам напрямую | capability gateway, отсутствие ambient authority, песочница воркера |
| выдать себя за другой пакет | идентичность вызывающего восстанавливается runtime из сессии, а не передаётся приложением |
| нарисовать системный диалог | системные диалоги рисует только оболочка, область которой недостижима из origin приложения |
| выйти в сеть мимо прав | CSP запрещает внешние направления, сеть только через capability с областью по хосту |
| исчерпать ресурсы устройства | квоты драйверов и планировщика, ограниченные очереди, карантин падающих воркеров |
| злоупотребить выданными правами в пределах квот | метрики размечены по пакету и видны пользователю; право можно отозвать |

Последняя строка — признание границы: приложение, которому пользователь выдал доступ к
папке, может прочитать её содержимое. Технической защиты здесь нет, есть наблюдаемость и
отзыв.

### Обновление, расширяющее права

Расширение прав при обновлении не активируется автоматически: пакет переходит в
`pending-grant` и не запускается ни на одной ноде, пока пользователь не подтвердит
изменение. Подтверждение — запись в control log, поэтому оно не может быть подделано на
одной ноде.

### Сетевой наблюдатель

Взаимная аутентификация и шифрование на любом канале; данные шифруются на уровне записей и
blob, а не только в канале; обнаружение в локальной сети публикует вращающийся
идентификатор, а не постоянный.

Не защищено: факт обмена, объёмы и тайминги. Наблюдатель в локальной сети видит, что два
устройства обмениваются данными.

### Владелец хостинга облачной ноды

Полный доступ к ключам данных, находящимся на этой ноде. Меры — организационные, а не
технические: облачная нода предполагается на подконтрольном пользователю оборудовании;
namespace может быть помечен `no-cloud` и тогда не реплицируется туда ценой доступности;
для недоверенного хостинга существует `relay`.

### Узел ретрансляции

Не имеет ключей профиля, видит зашифрованные данные и метаданные маршрутизации. Обязан
проверять авторизацию по control log, чтобы отозванная нода не могла продолжать выкачивать
данные. Не защищено: анализ метаданных.

### Отозванное устройство

После отзыва: новая эпоха ключей данных, отказ в установлении сессий узлами, узнавшими об
отзыве, выпуск нового ростера для связанных пользователей.

Не защищено: данные, которые устройство уже получило, и период до того, как остальные узлы
узнают об отзыве. Это фиксируется как проектное решение: система без кворума не может
обеспечить мгновенный отзыв.

### Связанный пользователь

Получает ровно то, что ему выдано, проверяется на стороне владельца независимо от
предъявленного токена, квотируется, наблюдаем в журнале, отзывается одним действием.

Не защищено: копия файла, сделанная до отзыва, и сохранение прочитанного содержимого
другими средствами.

### Физический доступ к устройству

Ключ ноды хранится в платформенном хранилище и не экспортируется; профиль может требовать
разблокировки, при которой ключи данных остаются запечатанными; потерянное устройство
отзывается с другого устройства с полномочиями администратора.

Не защищено: включённое и разблокированное устройство. Защита данных в состоянии покоя
сверх платформенной — открытый вопрос.

### Компрометация одного устройства как точка входа

Ключевая мера — **двусторонняя проверка**: право инициатора делегировать и собственное
правило целевой ноды. Одностороннего разрешения недостаточно нигде: ни для запуска
процесса, ни для управления нодой, ни для доступа к оборудованию, ни для вызова
экспортированного API.

Дополнительно: delegation-токены ограничены по области, сроку и по умолчанию непереходящие;
управляющие действия журналируются на целевой ноде, включая отклонённые.

### Платформенное расширение

Устанавливается явным действием с отдельным подтверждением, подписывается отдельно, по
возможности исполняется в отдельном процессе, объявляет предоставляемые capabilities и не
получает автоматически прав основного процесса.

Остаточный риск признаётся: расширение входит в доверенную базу ноды. Поэтому драйверы —
слой, применяющий квоты и отзыв прав, — не доустанавливаются, а расширения ограничены
слоем механизма.

## Допущения

- платформенное хранилище ключей работает так, как заявлено;
- пользователь подтверждает добавление устройства и выдачу прав осознанно;
- драйверы и host adapters корректны и являются частью доверенной базы;
- ОС ноды не скомпрометирована;
- криптографические примитивы стойки, а их реализации проверены.

Каждое допущение — потенциальная точка отказа модели, и это фиксируется явно.

## От чего система не защищает

- удаление данных, уже полученных отозванным устройством;
- копию файла, сделанную получателем до отзыва доступа;
- компрометацию хоста облачной ноды, владеющей ключами данных;
- анализ метаданных транзитным узлом и наблюдателем канала;
- злоупотребление приложением правами, которые пользователь ему выдал;
- физический доступ к разблокированному устройству;
- ошибочное решение пользователя выдать право или подтвердить подключение;
- атаку на уровне ОС и оборудования ноды.

## Проверяемые критерии

- ни один сценарий не требует одностороннего разрешения для действия на другой ноде;
- отзыв права делает выданный handle непригодным немедленно;
- приложение не может обойти capability gateway ни через контейнер, ни через SDK;
- расширение прав не активируется без подтверждения, записанного в control log;
- отозванная нода не устанавливает сессии с узлами, знающими об отзыве;
- все управляющие действия над нодой журналируются, включая отклонённые;
- узел без ключей профиля не может прочитать ни одну запись и ни один blob.

## Открытые вопросы

- нужна ли дополнительная защита данных в состоянии покоя сверх платформенной и на каких
  устройствах;
- какой уровень проверки требовать от платформенных расширений сторонних издателей;
- как выражать пользователю совокупный риск: набор прав, выданных приложению, и то, что он
  означает вместе.
