# Принципы и инварианты K-OS

Статус: перенесено из прежних документов, требует ревизии.  
Назначение: зафиксировать сквозные архитектурные принципы, которым обязаны следовать все подсистемы.

Связанные документы: [видение](./01-vision.md), [слои системы](../02-architecture/01-layers.md), [критерии корректности](../02-architecture/10-correctness-criteria.md).


1. **Пакет является единицей установки.** Пользователь устанавливает приложение целиком, а не отдельно UI и его фоновые сервисы.
2. **Компонент является единицей исполнения.** Один пакет может содержать Web UI, workers и команды с разными жизненными циклами.
3. **Frontend не имеет прямого доступа к Tauri-командам, ОС и host adapters.** Он обращается только к публичному capability API K-OS.
4. **Пользовательский код считается недоверенным.** Права выдаются пакету явно и проверяются при каждом обращении к защищённой возможности.
5. **Состояние прозрачно, исполнение и ресурсы — нет.** Данные и установленные приложения выглядят одинаково на всех устройствах пользователя. Окна, соединения, процессы и оборудование всегда принадлежат конкретному устройству, поэтому API учитывает задержки, отсутствие устройства, отмену операций и конфликты состояния.
6. **Локальное и синхронизируемое состояние разделены семантически.** Приложение выбирает класс данных, а не физический каталог.
7. **Host adapter реализует механизм, driver управляет ресурсом, service реализует функцию.** Эти роли не смешиваются.
8. **Фоновая работа преимущественно событийная.** Постоянные пользовательские процессы являются исключением и требуют отдельного разрешения.
9. **Установка и исполнение разделены.** Приложение может быть установлено в профиле пользователя, но отдельный компонент исполняется только на совместимом и выбранном runtime узле.
10. **Неоднородность узлов является частью модели.** Наличие UI, фонового исполнения, оборудования и локальных данных на конкретном устройстве не предполагается автоматически.
11. **Контракты важнее реализаций.** Публичные capability interfaces, форматы package и логические классы состояния не зависят от конкретного WebView, WASM runtime, database engine или network transport.
12. **Детерминированная тестируемость является архитектурным требованием.** Всё, что обращается к внешнему миру — время, случайность, файловая система, сеть, процессы — доступно только через host adapters с mock-реализациями. Ядро должно запускаться как несколько нод в одном процессе поверх симулированной среды.
13. **Ядро не зависит от UI.** Kernel собирается и работает headless, без Tauri и WebView. Наличие окна — свойство конкретного node, а не условие работы системы.
14. **Одно окно на устройство.** K-OS не строится вокруг оконного менеджера: системная оболочка и UI приложений сосуществуют в одном окне. Изоляция обеспечивается origin и capability gateway, а не отдельными окнами ОС.
