Статус: готов

Связанные документы: [видение](./01-vision.md), [открытые вопросы](./05-open-questions.md), [направления развития](../12-future/).

## Первая версия


В MVP входят:

- Tauri shell в режиме единого окна: системная оболочка и контейнер приложения;
- Linux, Windows и Android platform ports, а также headless-сборка Linux;
- встроенные Rust host adapters, включая `ClockAdapter`, `RandomAdapter`, `SystemAdapter` и `ProcessAdapter`;
- встроенные drivers/resource brokers;
- control plane: node identity, control log, capability registry;
- package manifest и базовый package manager;
- Web UI components и capability bridge;
- WebAssembly workers;
- lifecycle и event activation;
- namespaces `local`, `replicated`, `cache`, `secrets`, `files`;
- VFS с метаданными, blob store и материализацией по запросу;
- permissions, grants и capability handles;
- симуляционный харнесс и contract tests с первого дня;
- базовый стек: HTTP client, WebSocket client, файловая система, экспорт API приложения;
- создание сети, подключение ноды с интерфейсом и headless-ноды по коду;
- обнаружение в локальной сети и исходящие сессии к постоянно доступной ноде;
- облачная нода как форма поставки;
- системная оболочка: панель, launcher, диалоги прав, picker, конфликты, уведомления;
- системные приложения: настройки, файлы, магазин приложений.

Первая версия после MVP, в порядке зависимости:

1. слушающий сокет (`net.listen`) и WebSocket-сервер для внешних клиентов;
2. связывание сетей пользователей, обмен файлами и сообщениями;
3. реестр подключённых устройств, маршрутизация обращений, нода умного дома;
4. удалённое управление нодами и обмен доступом к устройствам;
5. realtime-каналы;
6. десктопная интеграция: демон, ярлыки, отдельные окна приложений;
7. режим launcher на Android;
8. платформенные расширения как механизм доустановки adapters.

В MVP не входят:

- устанавливаемые platform extension packages;
- пользовательские Rust dynamic libraries;
- пользовательские постоянно работающие daemons;
- полностью прозрачный distributed RPC;
- универсальный интерфейс для всех видов host adapters;
- мультиоконность;
- обещание одинаковых фоновых гарантий на desktop и mobile;
- macOS и iOS platform ports и связанный с ними код;
- одинаковое размещение всех components на всех nodes;
- совместное редактирование текста как тип реплицируемых данных.

## Порядок работ

Порядок определяется зависимостями, а не привлекательностью задач:

```text
control plane → host adapters → drivers → storage/VFS → app runtime
        ↓
сеть: сессии, репликация, control log
        ↓
оболочка и системные приложения → создание сети → облачная нода
        ↓
федерация → устройства → realtime → десктопная интеграция
```

Правило приоритета: сначала то, без чего нельзя проверить корректность (симуляция, contract
tests), затем то, что определяет публичные контракты (каталог capabilities, манифест,
модель состояния), и лишь затем формы поставки.
