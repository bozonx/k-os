## Что такое K-OS

K-OS — персональная распределённая среда приложений, работающая на всех устройствах
пользователя. Данные и приложения синхронизированы, поэтому с какого бы своего устройства
пользователь ни начал работу, он попадает в одну и ту же виртуальную среду: те же
установленные приложения, те же файлы, приблизительно то же состояние.

Способ достижения — **репликация состояния, а не удалённый доступ к чужому экрану**.
Приложение всегда запускается локально на том устройстве, которое пользователь взял в руки.

K-OS не заменяет ядро операционной системы. Это прикладная среда поверх системных API,
которая предоставляет собственную модель приложений, данных, прав и распределённого
исполнения.

## Продуктовое обещание

1. **Одна среда на всех устройствах.** Установленное приложение доступно везде, где оно
   совместимо с устройством; данные приложения приходят вместе с ним.
2. **Данные принадлежат пользователю.** Они хранятся на его устройствах, синхронизируются
   между ними и не требуют чужого сервера. Облачная нода — это его собственная нода, а не
   сервис поставщика.
3. **Сеть работает без интернета.** Достаточно локальной сети, прямого Bluetooth-соединения
   или mesh: связь между устройствами не проходит обязательным транзитом через внешний сервис.
4. **Устройства пользователя — это ресурсы одной среды.** Телефон может обратиться к
   оборудованию домашнего сервера так же, как к локальному, если это разрешено.

## Состав системы

### Слои исполнения

Приложениям **не предоставляется низкоуровневый доступ к IO**. Вместо него на нижнем
уровне находятся типизированные обёртки над возможностями платформы: HTTP client и server,
WebSocket client и server, MQTT client, обработка медиа, Git, GPIO и подобные. Под этими
обёртками работают платформозависимые реализации.

```text
Приложения          frontend на любой веб-технологии + необязательный backend в WASM
Воркеры             фоновая обработка, реакция на события, тяжёлые расчёты
Системные services  хранилище, синхронизация, планировщик, уведомления, медиа
Драйверы            владение ресурсом, мультиплексирование, квоты
Host adapters       платформозависимые примитивы ОС и оборудования
```

Драйверы интегрированы в систему и не устанавливаются пользователем: от их качества
зависит корректность всей среды. Платформенные расширения, добавляющие поддержку
оборудования или протоколов, могут устанавливаться отдельно и с отдельным уровнем доверия.

Подробнее: [слои системы](../02-architecture/01-layers.md),
[host adapters](../02-architecture/04-host-adapters.md),
[драйверы](../02-architecture/05-drivers.md),
[базовый стек HTTP, WebSocket и файлов](../02-architecture/12-base-stack.md),

### Приложения

Приложение — это в первую очередь frontend, работающий с предоставленным API: изолированная
база данных приложения, изолированная файловая система приложения, события, команды.
Frontend можно писать на любой веб-технологии.

Backend приложения необязателен и запускается изолированно в WebAssembly. Он нужен для
воркеров, сложных расчётов, работы с GPU и фоновой активности без открытого UI.

Подробнее: [модель приложения](../03-apps/01-app-model.md),
[данные приложения](../03-apps/06-app-data-api.md).

### Сеть пользователя

Все устройства пользователя стремятся объединиться в одну сеть и синхронизировать данные.
В этой сети:

- можно обратиться напрямую к конкретному устройству и вызвать API приложений и сервисов,
  которые его экспортировали, — всё под контролем прав;
- часы устройств сверяются, чтобы точнее упорядочивать изменения при синхронизации;
- realtime-возможности доступны приложениям, которым они действительно нужны; это не
  основной режим, поскольку предполагается, что всеми устройствами управляет один человек;
- события и push-уведомления доставляются пользователю через выбранный обработчик, а не
  всеми нодами одновременно.

Подробнее: [сеть пользователя](../06-network/01-overview.md),
[realtime](../06-network/09-realtime.md), [события и push](../06-network/10-events-and-push.md).

### Взаимодействие между пользователями

Пользователи могут связать свои сети и после этого общаться, обмениваться файлами и
предоставлять доступ к устройствам. Обмен идёт между сетями: конкретное устройство
собеседника не важно, важно, чтобы была доступна хотя бы одна его нода.

Ключевое правило: **данные принадлежат их владельцу**. Файлы по возможности не копируются
собеседнику, ему открывается доступ в сети владельца, и владелец может закрыть этот доступ.

Подробнее: [взаимодействие пользователей](../08-federation/01-model.md).

### Устройства и IoT

Помимо приложений и файлов среда управляет подключёнными устройствами, в том числе
подключёнными к другой ноде. Нода может быть контроллером умного дома и работать headless.
Запросы маршрутизируются через сеть пользователя к ноде, к которой подключено устройство,
поэтому взаимодействие выглядит так, будто устройство подключено к текущему компьютеру.

Подробнее: [устройства и IoT](../09-devices/01-model.md).

## Формы поставки

| Форма | Роль |
|---|---|
| Десктоп | полноценная нода с UI, может создать сеть или присоединиться к существующей |
| Мобильное устройство | полноценная нода с UI: Android и мобильные Linux-системы |
| Облачная нода | headless: постоянная доступность, хранение, маршрутизация, шлюз в интернет |
| Нода умного дома | headless: доступ к подключённому оборудованию |
| Relay | транзит зашифрованных данных без доступа к ним |

Подробнее: [клиенты](../10-clients/01-desktop.md), [облачная нода](../10-clients/03-cloud-node.md).

## Ключевые решения одним взглядом

| Решение | Следствие |
|---|---|
| Состояние прозрачно, исполнение и ресурсы — нет | окна, соединения, процессы и оборудование принадлежат конкретному устройству |
| Реплицируется операция, а не файл базы данных | побайтовая синхронизация файлов движка хранения запрещена |
| Права проверяются в доверенном ядре | frontend не может обойти capability API |
| Ядро не зависит от UI | система собирается и работает headless |
| Отсутствие возможности — нормальное состояние | приложение обязано обрабатывать `unavailable`, а не полагаться на её наличие |
| Кворум не требуется для обычной работы | личные устройства большую часть времени выключены |

## Границы

K-OS не обещает:

- работу приложения без совместимого устройства в сети пользователя;
- одинаковые гарантии фонового исполнения на desktop и mobile;
- удалённый доступ к экрану другого устройства как способ работы с приложением;
- exactly-once семантику распределённых операций по умолчанию.

## Дальнейшее развитие

За пределами основной системы рассматриваются: распределённое обнаружение нод через
bootstrap-узлы, рынок вычислительных ресурсов с вознаграждением и публичные сервисы поверх
пользовательских данных. Эти направления описаны в [разделе 13](../13-future/) и не влияют
на решения основной поставки.
