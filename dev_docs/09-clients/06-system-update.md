# Обновление системы и сходимость версий

Статус: готов  
Назначение: определить, как обновляется сам runtime K-OS на каждой платформе, как профиль
ведёт себя при неоднородных версиях нод и как обновление одного устройства приводит к
обновлению остальных, никого не принуждая.

## Разделение: версия ноды и версия профиля

**Версия runtime — свойство ноды, а не профиля.** Приложение установлено в профиле, но
исполняется кодом конкретного устройства, а устройства обновляются в разное время: телефон
через магазин, десктоп сам, сервер — когда до него дойдут руки.

```text
версия runtime            у каждой ноды своя, публикуется в дескрипторе возможностей
активная версия пакета    одна на профиль, см. распространение приложений
версия схемы control log  общая; расхождение major останавливает применение лога
```

Профиль поэтому не имеет «своей версии». Он имеет **разброс версий**, который вычисляется
из дескрипторов нод и показывается пользователю: «обновлены 3 устройства из 4, телефон
остаётся на прежней версии».

## Обновление ноды на разных платформах

Способ доставки принадлежит платформе, и обещать одинаковое поведение нельзя:

| Сборка | Механизм | Согласие пользователя |
|---|---|---|
| desktop Linux, Windows | собственное обновление либо пакетный менеджер дистрибутива | требуется при установке, дальше по настройке |
| Android | APK: магазин или установка вручную | **всегда требуется**, платформа не позволяет иначе |
| mobile Linux | как desktop | как desktop |
| headless-cloud, headless-device | пакет дистрибутива или образ контейнера, обычно администратором | по настройке хоста |

Из этого следует запрет, который важнее удобства: **система не обещает молчаливого
самообновления и не делает вид, что может обновить телефон сама**. Она может заранее
загрузить сборку и предложить установку в один шаг — решение остаётся за платформой и
пользователем.

## Сборка runtime как обычный артефакт

Сборка K-OS для платформы — такое же неизменяемое содержимое, адресуемое хешем и подписанное
ключом поставщика, как артефакт пакета. Из этого бесплатно следуют три вещи:

- **ноды профиля раздают сборки друг другу.** Десктоп с быстрым каналом загружает сборку и
  отдаёт её ноутбуку и серверу по локальной сети;
- **нода вправе держать сборку под чужую платформу.** Десктоп загружает Android-сборку для
  телефона того же профиля — телефон обновляется, не расходуя мобильный трафик;
- **сборки распространяются [открытым кешем](../06-network/11-public-artifact-cache.md)**
  наравне с пакетами. В локальной сети без интернета достаточно одного устройства,
  побывавшего онлайн.

Проверка подписи и хешей выполняется на устройстве, которое устанавливает сборку, независимо
от того, откуда она пришла. Установка производится платформенным механизмом, а не
подменой файлов на диске.

## Как обновление одного устройства подтягивает остальные

Принуждение исключено: нода, которую не обновили, остаётся полноправным членом профиля.
Давление создаётся не запретами, а связью версий пакетов с версией runtime.

```text
На ноутбуке обновился runtime
        ↓
в образе новой сборки — новые версии системных пакетов
        ↓
ноутбук публикует кандидатов в реплицируемом состоянии
        ↓
профиль переходит в staged: ноды тянут артефакты и публикуют готовность
        ↓
телефон со старым runtime не может быть готов: версия требует нового runtime
        ↓
пользователю на телефоне показано: доступно обновление системы,
сборка уже загружена с ноутбука, установка — одно подтверждение
        ↓
после установки телефон готов, версия активируется на всём профиле
```

Правила, делающие это безопасным:

- **версия пакета, требующая более нового runtime, не активируется**, пока не готовы ноды,
  на которых пакет может исполняться. Иначе обновление ноутбука выключало бы приложение на
  телефоне;
- **ожидание конечно**: нода, вышедшая за горизонт отставания, не блокирует активацию. Она
  догонит, когда появится;
- **пользователь вправе активировать раньше**, увидев, какие устройства временно останутся
  без приложения;
- пока системные пакеты поставляются в комплекте, их версия совпадает с версией сборки, см.
  [распространение](../03-apps/07-distribution.md). Когда они получат собственные версии,
  схема не изменится: изменится только источник кандидатов.

## Отставшая нода

Что она **может**: синхронизировать состояние, файлы и сообщения, запускать пакеты, версии
которых ей по силам, участвовать в раздаче содержимого, оставаться в профиле неограниченно
долго.

Что она **не может**, и это показывается явно:

| Ограничение | Причина | Где определено |
|---|---|---|
| не применяет операции с версией схемы выше поддерживаемой, а помещает их в карантин | молчаливое отбрасывание уничтожило бы данные | [база данных](../05-storage/02-database.md) |
| не запускает пакеты, требующие более нового runtime | несовместимый контракт capabilities | [манифест](../03-apps/02-manifest.md) |
| прекращает применение control log при более высокой major-версии схемы записи | решение об авторизации по неполному состоянию недопустимо | [control log](../06-network/03-control-log.md) |

Во всех трёх случаях нода **сообщает пользователю, что её нужно обновить**, и не притворяется
работающей. Молчаливая деградация запрещена: пользователь, у которого на телефоне часть
данных «просто не появилась», не имеет способа понять причину.

Понижение версии runtime не поддерживается системой: откат выполняется платформенными
средствами и означает возврат к состоянию, в котором данные, записанные новой схемой, могут
быть нечитаемы. Это состояние показывается, а не обнаруживается позже.

## Границы

Обновление системы не решает и не обязано решать:

- **доставку в обход платформы.** Android-сборка ставится как APK, и никакой механизм
  профиля этого не меняет;
- **синхронность обновления.** Одновременное обновление всех устройств не гарантируется
  никогда, и вся модель построена на том, что его не будет;
- **обновление ядра ОС, драйверов хоста и платформенных расширений** — у них собственные
  механизмы, см. [расширяемость](../02-architecture/08-extensibility.md).

## Проверяемые критерии

- профиль работает при неоднородных версиях runtime неограниченно долго;
- обновление одной ноды не выключает приложение на остальных;
- нода, не понимающая операцию, помещает её в карантин и сообщает о необходимости
  обновления, а не отбрасывает;
- сборка runtime, полученная от другой ноды или из открытого кеша, проходит ту же проверку
  подписи, что и загруженная из интернета;
- телефон обновляется, получив сборку по локальной сети, без обращения в интернет со своего
  канала;
- система нигде не устанавливает сборку без согласия, требуемого платформой;
- разброс версий нод виден пользователю с любого устройства.

## Открытые вопросы

- нужен ли верхний предел разброса версий, после которого профиль переходит в режим «только
  чтение» на отставших нодах, или достаточно карантина операций;
- как поставлять сборки для платформ, магазины которых запрещают доставку исполняемого кода
  мимо себя, если такие платформы появятся в списке целевых;
- кто и по какому правилу решает, что версия runtime более не поддерживается: поставщик
  через фид или профиль по возрасту сборки.
