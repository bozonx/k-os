# Виртуальная файловая система

Статус: перенесено из прежних документов, требует ревизии.  
Назначение: определить единое пространство имён файлов, состояния файла, семантику чтения и доступ за пределы VFS.

Связанные документы: [blob store и материализация](./04-blobs-and-materialization.md), [обмен файлами между пользователями](../08-federation/02-sharing.md).


VFS — единое платформонезависимое пространство имён, одинаковое на всех nodes профиля. Это не общий POSIX-каталог: одинаково выглядит дерево, а не физическое размещение содержимого.

```text
/apps/<package-id>/            артефакты пакета, только чтение, реплицируются
/data/<package-id>/
        replicated/            app.data.replicated
        local/                 app.data.local, своё на каждом node
        cache/                 app.cache, вытесняемо
        files/                 app.files
/user/                         пользовательские файлы: документы, медиа
/profile/                      состояние профиля: реестр пакетов, настройки, grants
/nodes/<node-id>/              локальные пространства конкретных nodes
/mnt/<mount-id>/               внешние монтирования за пределами VFS
```

Приложение по умолчанию видит только своё поддерево в `/data/<own-package-id>/`. Всё остальное требует отдельной capability.

### Правила путей

Пути платформонезависимы, поэтому ограничения являются объединением ограничений всех целевых платформ:

- разделитель `/`, абсолютные пути;
- кодировка UTF-8 в нормализации NFC;
- регистр значим и сохраняется, но два имени в одном каталоге, различающиеся только регистром, запрещены — иначе дерево разойдётся между Linux и Windows;
- запрещены управляющие символы и `\ / : * ? " < > |`;
- запрещены зарезервированные имена Windows: `CON`, `PRN`, `AUX`, `NUL`, `COM1..9`, `LPT1..9`;
- запрещены завершающие точка и пробел;
- ограничение длины компонента имени и общей длины пути объявляется в контракте.

Проверка выполняется при записи, а не при чтении: недопустимое имя не должно попадать в реплицируемые метаданные.

### Идентичность файла

Файл имеет стабильный идентификатор, не зависящий от пути. Имя и родительский каталог являются атрибутами. Переименование и перемещение — операции над метаданными, а не удаление с созданием: открытый handle и ссылки остаются валидными.

### Состояния файла

Полное дерево видно на любом node, но содержимое присутствует не везде:

| Состояние | Значение |
|---|---|
| `materialized` | содержимое доступно локально |
| `metadata-only` | известны только метаданные |
| `fetching` | содержимое загружается |
| `partial` | доступна часть содержимого |
| `evicted` | содержимое было локально и вытеснено |
| `conflicted` | существуют параллельные версии |
| `unavailable` | ни один доступный node не содержит содержимого |

Это состояние является частью публичного API. Приложение обязано его обрабатывать, а не считать, что чтение всегда мгновенно.

### Семантика чтения

Режим доступа задаётся явно при открытии:

| Режим | Поведение |
|---|---|
| `auto` | при отсутствии содержимого запускает материализацию и ожидает в пределах deadline; при недостижимости источника возвращает `unavailable` |
| `require-local` | немедленная ошибка, если файл не материализован |
| `stream` | чтение диапазонов без полной материализации |

Дополнительно доступны `prefetch` и `pin`. Pin закрепляет путь или поддерево на конкретном node и защищает его от вытеснения в пределах квоты.

Режим по умолчанию — `auto`. Скрытая блокирующая загрузка без deadline не допускается ни в одном режиме.

### Доступ за пределы VFS

Доступ к хостовой файловой системе возможен только через явное внешнее монтирование:

- монтирование создаётся действием пользователя: системный picker каталога или настройка;
- каждое монтирование получает собственный идентификатор и собственные capabilities `files.external.<mount-id>.read|write`;
- содержимое внешних монтирований не реплицируется; между nodes передаётся только сам факт существования монтирования, чтобы пользователь понимал, где лежат данные;
- платформа может отозвать доступ в любой момент, что является нормальным состоянием, а не ошибкой;
- на Android внешний доступ выражается идентификаторами SAF, а не путями, и adapter обязан представлять это ограничение явно, не имитируя POSIX-семантику.

Механизм репликации метаданных, blob store, selective sync и разрешение конфликтов описаны в [карте документов](../README.md).
