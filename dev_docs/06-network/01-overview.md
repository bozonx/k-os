# Сеть пользователя: общая модель

Статус: перенесено из прежних документов, требует ревизии.  
Назначение: определить назначение сетевого слоя и то, что он гарантирует, а что нет.

Связанные документы: [профиль и ноды](../02-architecture/02-profile-and-nodes.md), [транспорт](./04-transport-and-discovery.md), [репликация](./07-replication.md).


Network layer связывает доверенные nodes одного profile через доступные каналы и предоставляет transport-independent основу для:

- синхронизации состояния и файлов;
- доставки событий;
- удалённого исполнения commands и jobs;
- передачи package artifacts;
- обнаружения nodes и оценки их доступности.

Сеть не делает распределённые операции неотличимыми от локальных. Недоступность node, задержка, отмена, повтор, частичный результат и конфликт являются частью публичной семантики.

Ключевое продуктовое следствие модели: **состояние прозрачно, исполнение и ресурсы — нет**. Пользователь на любом своём устройстве видит те же приложения и те же данные. Но окно, соединение, GPIO-пин и запущенный процесс всегда принадлежат конкретному устройству.


## Требует дополнения

Из описания продукта следуют свойства сети, не отражённые в перенесённом тексте:

- все устройства пользователя стремятся объединиться в одну сеть и синхронизировать данные;
- можно обратиться напрямую к конкретному устройству: при этом доступно API приложений и
  сервисов, которые его экспортировали, под контролем прав;
- сверка часов между нодами — явное требование, а не деталь реализации: от неё зависит
  точность упорядочивания при синхронизации, см. [модель времени](./05-time.md);
- realtime-возможности выделены в [отдельный документ](./09-realtime.md) и не являются
  основным режимом работы;
- доставка событий пользователю описана в [документе о событиях и push](./10-events-and-push.md).
