# Control log профиля

Статус: перенесено из прежних документов, требует ревизии.  
Назначение: описать журнал состава профиля и прав: содержимое, устройство лога и правила слияния.

Связанные документы: [identity и доверие](./02-identity-and-trust.md), [модель capabilities](../04-capabilities/01-model.md).


Control log — единственная часть системы, для которой требуется согласованный порядок и строгая проверка авторизации. Всё остальное состояние использует более слабые модели.

Содержимое control log:

```text
profile-created
node-enrolled
node-revoked
node-role-changed
admin-granted
admin-revoked
key-epoch-created
package-installed
package-version-activated
package-removed
grant-added
grant-revoked
```

## Устройство лога

Control log — это hash-linked DAG подписанных записей, а не quorum-based журнал. Каждая запись содержит хеши родительских записей, идентификатор подписавшего node и подпись.

Consensus-алгоритм с кворумом здесь неприменим: личные устройства большую часть времени выключены, и требовать кворум для добавления устройства или выдачи разрешения означало бы неработоспособность системы.

## Правила слияния

- запись валидна, если подписавший обладал требуемыми полномочиями в том состоянии DAG, на которое ссылается;
- параллельные ветви объединяются объединением записей;
- **безопасность имеет приоритет**: при конфликте `node-revoked` побеждает конкурирующий `node-enrolled` или `admin-granted` для того же субъекта;
- взаимный revocation двух admin-устройств приводит к отзыву обоих. Это осознанно выбранный безопасный исход; восстановление выполняется новым enrollment, подписанным оставшимся admin или profile root key;
- записи монотонны: отменить запись можно только новой записью, но не удалением.

## Ограничение области

В control log попадает только то, что определяет доверие и состав профиля. Пользовательские данные, содержимое приложений и оперативное состояние в control log не помещаются.
