# Каналы, транспорт и обнаружение

Статус: готов  
Назначение: описать link adapters, выбор канала, мультипуть и приватность обнаружения.

Связанные документы: [NAT и достижимость](./10-nat-and-reachability.md), [realtime](../03-apps/09-realtime.md).


## Слои

```text
Node identity and trust (control log)
          ↓
Peer discovery and reachability
          ↓
Link adapters: LAN / Internet / BLE
          ↓
Authenticated encrypted sessions
          ↓
Multipath connection manager
          ↓
Streams / messages / datagrams
          ↓
Replication / RPC / events / blob transfer
```

Link adapter отвечает только за конкретный канал. Identity, шифрование, повторная установка session, маршрутизация и прикладные сообщения не дублируются отдельно для LAN, Internet и Bluetooth.

## Свойства каналов

| Канал | Назначение | Ограничения |
|---|---|---|
| LAN | основной путь: репликация, blobs, RPC | требуется общая сеть, изоляция клиентов на части Wi-Fi-сетей |
| Internet | доступность вне дома, доставка через cloud/relay | латентность, metered-трафик, NAT |
| BLE | discovery, enrollment, control-сообщения, малые дельты | низкая пропускная способность, малый MTU, ограничения фонового режима |

BLE не используется для передачи blobs и полной синхронизации. Его роль — обнаружение, начальная установка доверия и обмен небольшими управляющими сообщениями, в том числе для поднятия LAN-соединения.

## Выбор канала

Локальный канал предпочтителен по умолчанию, но порядок не задан жёстко. Connection manager оценивает:

- reachability и стабильность;
- latency и bandwidth;
- metered/unmetered status;
- энергетическую стоимость;
- доверие к каналу;
- максимальный размер передачи;
- возможность streaming и resume;
- доступность в фоне;
- стоимость установки соединения.

Session может менять link без изменения identity peer и в дальнейшем использовать несколько links одновременно.

## Discovery и приватность

Обнаружение в локальной сети не должно раскрывать стабильный идентификатор пользователя или устройства. В эфир публикуется вращающийся идентификатор, вычисляемый из ключа профиля; реальная identity раскрывается только после аутентифицированного handshake.


## Работа без интернета

Сеть пользователя и взаимодействие между пользователями обязаны работать без интернета:
достаточно локальной сети, прямого Bluetooth-соединения или mesh. Обязательного транзита
через внешний сервис в модели нет.

Отсюда требование к слою link adapters: **добавление нового канала не затрагивает identity,
шифрование, сессии и прикладные протоколы**. Канал предоставляет только доставку байт между
двумя точками; всё остальное построено над ним один раз.

| Канал | Базовая поставка | Роль |
|---|---|---|
| LAN | да | основной путь: репликация, blobs, RPC |
| Internet | да | доступность вне дома, доставка через постоянно доступную ноду или ретранслятор |
| BLE | да | обнаружение, подключение, малые управляющие сообщения |
| mesh | нет, устанавливается дополнительно | связь без инфраструктуры |
| проводные каналы, включая последовательный порт | нет, устанавливается дополнительно | специальные сценарии |

Дополнительные каналы поставляются платформенными расширениями на слое adapters, см.
[расширяемость](../02-architecture/08-extensibility.md). Вопросы достижимости за NAT — в
[отдельном документе](./10-nat-and-reachability.md).
