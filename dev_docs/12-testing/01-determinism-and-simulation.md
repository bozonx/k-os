# Детерминированная тестируемость и симуляция

Статус: перенесено из прежних документов, требует ревизии.  
Назначение: зафиксировать архитектурные ограничения, делающие возможной детерминированную симуляцию кластера, и проверяемые инварианты.

Связанные документы: [host adapters](../02-architecture/04-host-adapters.md), [структура кодовой базы](../02-architecture/08-workspace.md), [модель времени](../06-network/05-time.md).


Требования этого раздела являются архитектурными ограничениями, а не рекомендациями по тестированию. Детерминированную симуляцию распределённой системы невозможно добавить позднее без переписывания ядра, поэтому ограничения фиксируются до начала реализации.

## Запреты в коде ядра

В `kernel`, services, drivers и app-runtime запрещены:

- прямое обращение к системным часам вместо `ClockAdapter`;
- прямое использование генератора случайных чисел вместо `RandomAdapter`;
- прямые вызовы файловой системы, сокетов, процессов и платформенных API в обход host adapters;
- глобальное изменяемое состояние и синглтоны, препятствующие запуску нескольких экземпляров ядра в одном процессе;
- скрытые фоновые задачи, не привязанные к явному scheduler и не останавливаемые при остановке экземпляра.

Соблюдение проверяется автоматически в CI, а не только на code review.

## Уровни проверки

| Уровень | Что проверяет |
|---|---|
| Contract tests | общий набор тестов для всех реализаций одного host adapter, включая mock |
| Компонентные тесты | service или driver поверх mock adapters |
| Симуляция кластера | несколько нод в одном процессе на симулированных сети и времени |
| Платформенные тесты | реальные adapters на целевых ОС |
| End-to-end | системная оболочка, установка пакета, запуск компонентов |

Contract tests существенны: они гарантируют, что Linux-, Windows-, Android- и mock-реализации ведут себя одинаково там, где контракт это обещает, и явно расходятся там, где различие объявлено.

## Симуляция

Симуляционный харнесс запускает N нод в одном процессе и управляет:

- виртуальным временем и таймерами;
- задержкой, потерей, дублированием и переупорядочиванием сообщений;
- разделением сети и восстановлением связи;
- падением и перезапуском node в произвольный момент;
- расхождением часов между нодами;
- заполнением диска и ошибками записи;
- повреждением blob и обрывом передачи.

Прогон детерминирован по seed. Найденный сбой воспроизводится по номеру seed, что делает отладку распределённых дефектов возможной.

## Проверяемые инварианты

- сходимость реплик после восстановления связи;
- отсутствие потери подтверждённой mutation при падении в любой точке;
- отсутствие двойного внешнего side effect без корректного fencing token;
- невозможность обойти capability gateway ни из UI, ни из worker;
- невозможность получить admin-полномочия без валидной цепочки подписей;
- невозможность материализовать файл с содержимым, не соответствующим хешу;
- освобождение всех capability handles при завершении владельца.


## Симуляция сети


Требования являются архитектурными, а не рекомендациями: их невозможно добавить позднее без переписывания.

- каждый link adapter имеет mock-реализацию;
- ядро запускается как N нод в одном процессе поверх симулированной сети;
- симулятор управляет: задержкой, потерей, дублированием, переупорядочиванием сообщений, разделением сети, падением и перезапуском node, расхождением часов, заполнением диска, повреждением blob;
- время в симуляции виртуальное, через `ClockAdapter`;
- прогон детерминирован по seed и воспроизводится по записи.

Проверяемые инварианты:

- сходимость: при прекращении изменений и восстановлении связи все nodes приходят к одному состоянию;
- отсутствие потери подтверждённой mutation при падении в любой момент;
- отсутствие двойного внешнего side effect без корректного fencing token;
- невозможность получения admin-полномочий без валидной цепочки подписей в control log;
- отсутствие материализации файла с содержимым, не соответствующим хешу.
