# Поддерживаемые платформы

Статус: перенесено из прежних документов, требует ревизии.  
Назначение: зафиксировать целевые платформы, требования к переносимости и правила platform-specific кода.

Связанные документы: [десктоп](../10-clients/01-desktop.md), [мобильные устройства](../10-clients/02-mobile.md), [host adapters](./04-host-adapters.md).


Основными целевыми платформами являются:

- Linux — desktop и headless;
- Windows — desktop;
- Android — mobile.

Отдельной целью сборки является **headless Linux node** без Tauri, WebView и системного UI. Это форма запуска cloud node. Требование фиксируется на уровне зависимостей: crate `kernel` и все services не зависят от `tauri`, интеграция с окном локализована в `tauri-host`.

Архитектурные контракты не должны без необходимости зависеть от особенностей этих трёх платформ, однако текущая реализация и MVP не обязаны поддерживать Apple platforms. macOS и iOS могут быть добавлены в будущем как отдельные platform ports после проверки ограничений исполнения, распространения пакетов и фоновой работы.

Для будущей переносимости достаточно соблюдать следующие правила:

- platform-specific код находится за host adapter contracts;
- manifest позволяет объявить совместимость component с платформой и архитектурой;
- service API не содержит Linux-, Windows- или Android-specific типов;
- отсутствие capability на платформе является нормальным состоянием;
- runtime не предполагает наличие process spawning, постоянного background execution или общей POSIX filesystem.

Не требуется заранее реализовывать Apple adapters, альтернативный mobile runtime или специальные ограничения App Store. Возможность будущего port обеспечивается границами контрактов, а не неиспользуемым кодом.


## Требует дополнения

Из описания продукта следуют уточнения, не отражённые в перенесённом тексте:

- мобильная цель — не только Android, но и мобильные Linux-системы; нужно определить, что
  из решений для десктопного Linux переносится на них без изменений;
- Apple-платформы не поддерживаются и не планируются в обозримом объёме работ;
- headless-сборка используется в двух разных ролях: облачная нода и нода умного дома без
  экрана; требования к ним частично различаются.
