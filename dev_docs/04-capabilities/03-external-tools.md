# Внешние инструменты

Статус: перенесено из прежних документов, требует ревизии.  
Назначение: зафиксировать модель «capability с несколькими взаимозаменяемыми backends» для FFmpeg, Git и подобных инструментов.

Связанные документы: [модель расширяемости](../02-architecture/09-extensibility.md), [процессы хоста](./04-host-processes.md).


Ранняя формулировка относила FFmpeg и Git к sidecar-процессам. Это противоречит требованию платформонезависимости: на Android запуск произвольных процессов недоступен, а оба инструмента объявлены базовыми возможностями системы.

Принятая модель: **внешний инструмент — это capability с несколькими взаимозаменяемыми backends**.

```text
capability: media.transcode / media.probe / vcs.git
        │
        ├── in-process library      предпочтительный backend
        ├── bundled sidecar         desktop, где библиотека неполна
        └── remote execution        исполнение на другом node профиля
```

| Capability | Desktop | Android | Fallback |
|---|---|---|---|
| `media.probe`, `media.transcode` | связанная библиотека или поставляемый бинарь | связанная библиотека сборки для мобильной платформы | удалённое исполнение на capable node |
| `vcs.git` | библиотечная реализация в процессе | та же библиотечная реализация | удалённое исполнение |

Правила:

1. **Публичный API — типизированное описание задачи, а не строка аргументов.** Транскодирование описывается входом, выходом, контейнером, кодеками и структурированными параметрами; операция Git — типом операции, ссылками и путями. Только так один и тот же вызов работает на всех backends.
2. **Сырые аргументы — отдельная capability.** Escape hatch вида «передать произвольные аргументы FFmpeg» существует, но требует отдельного разрешения, и компонент, использующий его, обязан объявить платформы, на которых он работает. Переносимость таких вызовов не гарантируется.
3. **Выбор backend делает runtime, а не приложение.** Приложение может узнать доступные возможности и ограничения, но не выбирает способ исполнения.
4. **Недоступность backend — явное состояние.** Если ни локального, ни удалённого backend нет, вызов возвращает `unavailable`, а не деградирует молча.

Тот же принцип применяется к любому будущему тяжёлому инструменту: сначала capability и типизированный контракт, только потом вопрос, чем он реализован на конкретной платформе.
