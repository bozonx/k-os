# Frontend приложения

Статус: готов  
Назначение: описать, как устроен интерфейс приложения: контейнер и его изоляция, загрузка
ресурсов, доступ к системному API, жизненный цикл представления, навигация и взаимодействие
с другими приложениями.

Связанные документы: [изоляция](../10-security/01-isolation.md),
[системная оболочка](../09-clients/05-system-shell.md), [десктоп](../09-clients/02-desktop.md),
[мобильный клиент](../09-clients/03-mobile.md), [данные приложения](./06-app-data-api.md),

## Модель

Интерфейс приложения — это web-документ, загружаемый в изолированный контейнер сеанса
оболочки. Разработчик использует любую web-технологию: React, Vue, Svelte, обычный
JavaScript, Canvas, WebGL, WebGPU.

```text
Сеанс оболочки ноды
├── Shell view   доверенный origin: панель, launcher, системные диалоги
└── App view     origin приложения: документ пакета и его capability bridge
```

Web UI не является обязательным компонентом: на headless-ноде он не запускается вовсе, и
приложение обязано это допускать. Обратное тоже верно — приложение может состоять только из
интерфейса, без единого воркера.

## Контейнер

Интерфейс приложения выполняется в контейнере с собственным origin, выделяемым системой по
package ID: строгий CSP формирует доверенный runtime, удалённый исполняемый код и произвольная
навигация запрещены, доступа к контексту оболочки нет, а при перезагрузке документа создаётся
новая сессия bridge и отзываются старые handles. Полный перечень требований и обоснование —
в [изоляции приложений](../10-security/01-isolation.md); здесь описаны только следствия для
разработчика интерфейса.

Рассматриваются два способа реализации контейнера:

| Вариант | Плюсы | Риски |
|---|---|---|
| `iframe` с отдельным origin | один WebView, одинаковое поведение на платформах | изоляция зависит от корректности origin-разделения в движке; идентификация вызывающего frame требует проверки |
| Встроенный дочерний WebView | более сильная изоляция, отдельное хранилище | поддержка на Android ограничена, поведение различается |

Выбор делается по результатам спайка на Android. До этого публичные контракты не зависят от
способа размещения: приложение работает с абстракцией `view`, а не с окном или frame.

Независимо от выбора действует правило: **контейнер — дополнительная граница изоляции, но
не основная**. Основная граница — capability gateway в Rust.

## Загрузка ресурсов

Документ и статические ресурсы приложения загружаются **из пакета через VFS**, а не из сети:

```text
kos-app://<package-id>/index.html   →  /app/<package-id>/code/ui/index.html
```

Следствия:

- приложение работает офлайн по построению; отдельного «офлайн-режима» не существует;
- содержимое ресурсов проверяется подписью пакета при материализации;
- CDN, внешние шрифты и аналитика по умолчанию недоступны: их загрузка запрещена CSP;
- обновление интерфейса происходит вместе с обновлением пакета, а не незаметно с сервера.

**Собственные сетевые вызовы браузерного API заблокированы.** `fetch`, `XMLHttpRequest`,
`WebSocket` и `EventSource` к внешним адресам не работают: `connect-src` не разрешает
внешние направления. Сеть доступна только через capability API (`kos.net.http`,
`kos.net.ws`), потому что только там проверяется право по хосту, применяются квоты, учёт
metered-трафика и возможность делегирования на другую ноду. Приложение, пытающееся
обратиться в сеть напрямую, получает ошибку браузера, а не молчаливо работающий обходной
путь.

## Доступ к системному API

```ts
import { kos } from "@kos/sdk";

const state = await kos.capabilities.query(["net.http:api.example.com"]);
if (state[0].state !== "available") {
  showUnavailable(state[0].remoteNodes);   // где эта возможность есть
}

const res = await kos.net.http.send({ method: "GET", url: "https://api.example.com/v1/x" });
```

Свойства SDK:

- **SDK не реализует безопасность.** Это типизированная оболочка над bridge; все проверки
  прав, идентичность вызывающего и квоты применяются на стороне ядра;
- **идентичность приложения не передаётся приложением.** Вызов имеет вид
  `storage.put(collection, id, value)`; пакет определяется runtime по сессии контейнера.
  Переданный приложением идентификатор доказательством личности не является;
- **всё асинхронно и отменяемо.** Каждый вызов принимает deadline и сигнал отмены;
- **ошибки типизированы** по общей таксономии: `denied`, `unavailable`, `revoked`,
  `conflict`, `quota-exceeded`, `deadline-exceeded`, `unreachable`, `result-unknown`;
- **`unavailable` — штатное состояние**, а не аварийное. Интерфейс обязан его показывать
  осмысленно и, по возможности, предлагать выполнение на другой ноде.

### Запрос прав

Приложение инициирует запрос, но не рисует его:

```ts
const granted = await kos.permissions.request("files.user.read");
```

Оболочка показывает диалог с обоснованием из манифеста; приложение получает только
результат. Отказ в необязательном праве — обычная ветвь исполнения. Отказ в обязательном
праве переводит компонент в состояние `not-permitted`: он не запускается вовсе, а не
работает в урезанном виде.

## Жизненный цикл представления

```text
create      создан контейнер, установлена сессия bridge
visible     представление активно
hidden      представление скрыто, но живо: таймеры замедляются
suspended   платформа приостановила выполнение
destroyed   представление закрыто, handles отозваны, сессия завершена
```

Правила:

- **представление может быть уничтожено в любой момент** — пользователь закрыл его,
  платформа выгрузила процесс, приложение обновилось. Несохранённое состояние
  интерфейса — ответственность приложения;
- **состояние интерфейса не является хранилищем данных.** Позиция прокрутки и открытая
  вкладка — `device-local` или вовсе эфемерное; данные живут в базе приложения;
- **закрытие представления не останавливает разрешённую фоновую задачу** и наоборот:
  это разные жизненные циклы;
- **handles не переживают перезагрузку документа**: открытое соединение, писатель файла,
  подписка создаются заново.

## Навигация и ссылки

- маршрутизация внутри приложения — его собственное дело; история браузера доступна;
- уход на внешний origin запрещён; открытие внешней ссылки — явный вызов
  `kos.shell.openExternal(url)`, который система показывает пользователю и может
  ограничить правом;
- глубокие ссылки в приложение имеют вид `kos://app/<package-id>/<path>` и работают как
  событие активации: приложение получает путь и открывает соответствующий экран;
- ссылка на файл VFS открывается системным приложением «Файлы» или приложением, объявившим
  обработку этого типа.

## Взаимодействие с другими приложениями

Прямой доступ к DOM или данным другого приложения невозможен. Разрешённые пути:

| Задача | Механизм |
|---|---|
| вызвать операцию другого пакета | `command.invoke` с областью, разрешённой обеими сторонами |
| получить файл от пользователя | системный picker оболочки |
| передать файл другому приложению | ссылка на объект VFS, а не копия содержимого |
| подписаться на событие | `events.subscribe` в пределах разрешённых тем |
| обратиться к API на другой ноде | `api.call` / `call-profile`, см. [базовый стек](../02-architecture/06-base-stack.md) |

Межпакетный вызов разрешается тремя сторонами: вызывающим (право), вызываемым (объявленный
экспорт) и системой (политика ноды).

## Графика и тяжёлые вычисления

Canvas, WebGL и WebGPU доступны там, где их даёт движок платформы; наличие проверяется
обычным способом и отсутствие является штатным. Тяжёлые вычисления не должны выполняться в
основном потоке интерфейса: для них существуют web workers внутри контейнера — для задач,
живущих ровно столько, сколько представление, — и [воркеры приложения](./05-backend-wasm.md)
в WebAssembly — для всего, что должно пережить закрытие интерфейса или выполниться на другой
ноде.

## Оформление и системные сведения

Приложение получает из низкочувствительной части `system.info` тему, плотность, размер и
ориентацию экрана, локаль и часовой пояс, чтобы согласовать интерфейс с системой. Это
чтение не требует отдельного права: от него зависит адаптация интерфейса, и его отсутствие
приводило бы к худшему результату без выигрыша в приватности. Чувствительные сведения —
имя устройства, список интерфейсов, серийные номера — требуют отдельного права, так как
служат для фингерпринтинга.

## Хранилища браузера

`localStorage`, IndexedDB и кэш контейнера считаются локальными и несинхронизируемыми: они
могут быть очищены вместе с данными контейнера и не переживают смену устройства. Их
допустимо использовать для временной оптимизации интерфейса и недопустимо — для основного
состояния. Основной способ хранения — асинхронное storage API K-OS.

## Проверяемые критерии

- приложение не может обратиться в сеть, минуя capability API;
- приложение не может загрузить исполняемый код извне пакета;
- приложение не может нарисовать интерфейс, неотличимый от системного запроса;
- идентичность пакета восстанавливается runtime и не передаётся приложением;
- перезагрузка документа отзывает сессию и все выданные handles;
- закрытие представления не останавливает разрешённую фоновую задачу;
- приложение работает офлайн без специального режима.
