# Frontend приложения

Статус: перенесено из прежних документов, требует ревизии.  
Назначение: описать размещение UI приложения в единственном окне устройства и требования к контейнеру.

Связанные документы: [изоляция](../11-security/02-isolation.md), [системная оболочка](../10-clients/04-system-shell.md), [десктоп](../10-clients/01-desktop.md).


K-OS использует **одно окно на устройство**. Мультиоконность не входит в модель: она различна на desktop и Android, усложняет lifecycle и не нужна для целевого продукта.

```text
Единственное окно устройства
├── System shell        доверенный UI: панель, launcher, переключатель, диалоги прав
└── App view            UI активного приложения, изолированный контейнер
```

Требования к контейнеру приложения:

- собственный origin на пакет, недостижимый из origin системной оболочки;
- строгий CSP, запрет загрузки удалённого исполняемого кода;
- запрет произвольной навигации и открытия внешних URL без разрешения;
- отсутствие доступа к DOM и глобальным объектам системной оболочки;
- отдельная сессия capability bridge, привязанная к origin;
- при перезагрузке или смене документа создаётся новая сессия, старые handles отзываются.

Рассматриваются два способа реализации контейнера:

| Вариант | Плюсы | Риски |
|---|---|---|
| `iframe` с отдельным origin | один WebView, одинаковое поведение на всех платформах | изоляция зависит от корректности origin-разделения внутри движка; идентификация вызывающего frame на стороне Rust требует проверки |
| Встроенный дочерний WebView | более сильная изоляция, отдельное хранилище | поддержка на Android ограничена, разное поведение платформ |

Выбор делается по результатам спайка на Android. До этого публичные контракты не должны зависеть от способа размещения: приложение работает с абстракцией `view`, а не с окном или frame.

Независимо от выбранного варианта действует правило: **container является дополнительной границей изоляции, но не основной**. Основная граница — capability gateway в Rust.

Диалоги выдачи прав, ввод учётных данных, picker файлов и подтверждение enrollment рисует только системная оболочка. Приложение не может отобразить собственный интерфейс, выглядящий как системный запрос.
