# Границы безопасности

Статус: перенесено из прежних документов, требует ревизии.  
Назначение: перечислить минимальные границы безопасности системы и сетевого слоя.

Связанные документы: [изоляция](./02-isolation.md), [модель угроз](./03-threat-model.md), [модель capabilities](../04-capabilities/01-model.md).


Минимальные границы безопасности:

- каждый package имеет отдельный namespace данных;
- Web UI работает с ограниченным bridge;
- workers исполняются в WebAssembly sandbox;
- системные capabilities запрещены по умолчанию;
- доступ к пользовательским файлам выдаётся через picker, scope или permission;
- credentials передаются через secrets service, а не хранятся в manifest;
- сетевые права могут ограничиваться доменами и протоколами;
- фоновые права выдаются отдельно;
- межпакетные вызовы разрешаются обеими сторонами и системой;
- удалённые вызовы аутентифицируют node и проверяются политикой обеих сторон;
- запуск программ хоста и доступ за пределы VFS относятся к отдельному классу прав;
- package update не может незаметно расширить permissions.


## Границы безопасности сетевого слоя


- каждый node имеет отдельную криптографическую identity в платформенном secure storage;
- добавление node требует enrollment с подтверждением человеком;
- транспорт использует взаимную аутентификацию и шифрование независимо от канала;
- данные шифруются на уровне записей и blobs, а не только в канале;
- удалённое исполнение требует явной ограниченной delegation capability и согласия целевого node;
- revocation узла влечёт создание новой key epoch;
- relay не получает ключей и обязан проверять авторизацию по control log;
- discovery не раскрывает стабильные идентификаторы до аутентификации.
