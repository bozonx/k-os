
## Системные пакеты
- системные пакеты идут в комплетке с системой, обновляются вместе с ней, но их можно не запускать, поставить отметку disabled
- при желании можно заменить системный пакет на свой, но у пользователя будет спрашиваться разрешение. тогда пакет ставится как обычный пакет

## Dev mode
- разработчик сам решает какие пакеты он использует
- для удобства пакеты представлены в виде объекта где некоторые можно заменить на свои, или исключить или наоборот включить
- разработчик сам создает ts файл где запускает squidlet

## System package in Prod mode
- Система копируется в `/local/system/dist`
- в `/local/packages/system` создается `package.json` в который прописаны зависимости системы и делается `npm install`

## Prod Пакеты
- все npm пакеты ставятся в `/local/system` и от туда запускаются
- все остальные пакеты ставятся в `/local/packages/PACKAGE_NAME` 
- пакеты запускаются через динамический импорт где будет указан либо локальный путь к пакету, либо имя пакета в node_modules

## New IoSet
- IoSetServer - в него регистрируются пакеты и иметт функцции callIo, on, off. Он посылая запрос ожидает ответ, поэтому формирует свое сообщение
- IoSetClient - иметт функцции callIo, on, off. тоже формирует сообщение
- между ними можно ставить свои каналы посылки и отправки сообщений - обычные сообщения для другого потока, ws
- IoManager - хранит все IoSet и при инициализацции создает Proxy для каждого Io с которым потом и работают драйверы. А внутри запросы идут на свои IoSet. Этот Proxy дает методы on и off и позволяет навешивать сколько угодно обработчиков, все остальные методы прозрачно проксируются

## Prod starter
- Запускается через electron или docker контейнер
- Резолвит root dir - если не указанно то использует путь по умолчанию ~/.local/share/k-os
- удостоверяется что собрал все env данные
- если нет root dir то запускает процесс установки
    - создает все папки и подпапки
    - создает /local/system/package.json где указывает заввисимость k-os той версии которая указана в дистирбутиве
    - выполняет npm install
    - создает index.js который запускает систему в прод режиме
    - если это первая установка то будут установленны базовые IO
- после 1й установки или если уже ранее установлена то запускает /local/system/index.js
    - подгружаются из конфига все установленные io
    - делаются IO set
    - резолвится какие драйвера нужно запустить и инициализируются
    - подгружается конфиг чтобы узнать какие сервисы enabled и запускаются сервисы
    - тоже с приложениями
- Если эта нода не подключена к сети то в консоле будет выведен код для считывания телефоном и в веб сервере (или в электрон) будет выбор - либо считать qr код либо создать новый инстанс

## Установка  env параметров
- если через electron
    - если root папки нет то показывает экран установки
    - при установке спрашивается env параметры даже если это устанока не первой ноды. потом они будут записанный в env config
    - если переданы env в процесс то эти данны подставляются в поля
- если запущенно через терминал (докер)
    - проверяет есть ли env config в стандартном расположении если нет то создается и выводится в консоль и выходит и предлагает внести в него изменения и снова запустить. А если есть конфиг или переменные окружения то сразу запускается минуя экран сбора параметров
    - в консоль пишет код который нужно считать телефоном
    - запускается UI http сервер для установки - там проходишь все шаги как и через electron
- если env конфиг уже создан или переданны все параметры то этап сбора env пропускается
