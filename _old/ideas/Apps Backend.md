## Внешняя сторона
- домен libr.net
- поддомен share.libr.net служит для расшаривания файлов и приложений
- выбирается мастер который находится в интернете и имеет долгий uptime либо можно самому его назначить. от передает свой ip на тот домен чтобы к нему всегда был доступ
- заходя на расшаренное приложение показывается экран логина если сессии нет, хотя впринципе можно и без него, сам юзер будет решать залогинить другого юзера снова или нет если тот разлогинился
- Когда юзер расшаривает приложение то создается ссылка с временным токеном логина на день. и новый юзер если её открывает то он сразу попадает в приложение залониненным под своим аккаунтом

## Запросы к бэкэнду из стороннего браузера
- для веб приложение предоставляется тонкий клиент для прозрачных запросов к серверным api и даже напрямую к api системы
- Но если приложение много пользовательское то имеет смысл заблокировать прямой доступ к системным api
- Важно что api на клиенте выглядит ровно так же как и на сервере поэтому обработчики запросов могут быть переиспользуемые

## На бэкэнде приложения
- Сначала работает служба приема сообщений похожая на express
- в него вставляется middleware который создает контекст и вызывает обработчики если пришло на /api
- сами обработчики написаны функционально без классов и желательно независимы от внешних контекстов. они должны работать только с переданным им контекстом и больше ни чем, тогда они будут независимы
- чтобы обработчики зарегистрировать в api используется use на объекте api приложения 
- объекты api будут как для доступа из UI, так и для внешнего доступа из системного api и может даже быть открытый api вво ввне
- в контексте будет сразу передана сессия в которой будет содержаться user_id для доступа к бд

## Структура
- SystemApiManager
    - принимает запросы только от локальных или удаленных (через SystemApiNetworkConnectorService) но принадлежащих сети данного пользователя приложения и сервисы
    - он не принимает само приложение, а только объект api и ввызовы идут на этот объект
    - запросы идут с использоанием спецциального токена через который проверяются права
- SystemApiNetworkConnectorService
    - делает только одну вещь - соединяет network с SystemApiManager
    - относится к пакету network
- SharedApiService
    - расшаривает апи по токену через внешний домен для расшаривания
    - он не принимает само приложение, а только объект api и вызовы идут на этот объект
- UiApiService
    - получает запрос функции приложения или сервиса
    - формирует контекст включая сессию и юзера
    - он не принимает само приложение, а только объект api и ввызовы идут на этот объект
- WsDriver, WsChannel
- SharedService
    - расшариввает файлы и приложения. их api и ui
- SystemApi
    - работает с серввисом Network и принимает запросы на системное api на этой машине
- AppsSybsustemService
    - регистрируется на ws канале для ui api
    - когда приходит запрос то передает к сервису UiApiService
